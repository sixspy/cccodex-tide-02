# 潮位报文归集台

港务水文组收到各潮位站的定长报文。归集员把一批报文贴进来，系统按站码和时刻解析、去重。实测（A）和插补（M）照常落库；**可疑（B）单独过一道理，不和实测混作一种落库**，出路由当日的旗设置决定。

解析全部在服务端完成，页面只提交原文。

## 技术栈

| 层 | 选型 |
|----|------|
| 接口 | Python FastAPI |
| 页面 | Vue 3，无组件库 |
| 数据库 | PostgreSQL 16 |

后端分层：`parser.py` 负责逐行解析（仍在服务端），`rules.py` 是可疑旗出路的纯规则（去向、策略取值、批次状态），`db.py` 负责落库与隔离队列，`app.py` 暴露接口。

归集与改旗设置共用一个 PostgreSQL 会话级 advisory lock：归集持共享锁，改策略持排他锁，所以“队列未腾空不许改旗设置”和“本批按哪条出路分流”在并发下也自洽。

## 可疑旗的出路

两条出路，写进策略栏后**本日不得更换**：

| 代码 | 名称 | 行为 |
|------|------|------|
| `quarantine` | 只进隔离队列 | 可疑旗不入库，只进隔离队列。默认出路 |
| `land_review` | 落库待复核 | 可疑旗允许落库，但详情行标“待复核”，与实测行区分 |

规则：

- **归集请求里的出路**（`suspect_exit`）只是校验，不能替人改当日策略。和策略栏不一致时，该行返回“旗出路偏了”，**不落库**。
- 同一站同一时刻被两次送去隔离，只留下先认领的一次，另一次记“旗争用”。
- 同一批里同一站同一时刻出现多行时，实测/插补（A、M）优先于可疑（B），同旗之间先到先得，其余记观测时刻重复。
- 质量旗为空的行直接进未接纳；观测时刻不是十二位数字的行同样进未接纳。
- **隔离队列尚未腾空（仍有待隔离行）时，不许改旗设置。**
- 策略栏当日已写入后，再写不同的出路一律被挡；未写入时可写入一次。
- 隔离行复核后状态转为“已复核”并腾出队列位置，但**留档仍占着该站该时刻**，不会因此允许同键的实测行后来落库；拒绝理由会区分“还在隔离队列待复核”与“已复核留档在隔离队列”。
- 复核完一批的隔离行后，批次状态会跟着从“待隔离”变成“已复核”。

## 页面上的四处

| 位置 | 读到什么 |
|------|----------|
| 归集列表 | 每批并列 待隔离数、已复核数、策略名；本批实际出路；请求是否偏离；可疑旗有没有入库 |
| 旗号详情 | 按站按旗汇总入库、待复核、隔离队列；可疑旗状态（已入库待复核 / 待隔离未入库 / 已复核未入库） |
| 旗设置 | 当日出路、可选出路与说明、锁定原因；档案员只读 |
| 隔离队列 | 每行隔离原因、认领人、状态，可逐行复核 |

## 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/batches` | 归集一批，可带 `suspect_exit` |
| GET | `/api/batches` | 归集列表，含待隔离数、已复核数、策略名、可疑旗是否入库 |
| GET | `/api/batches/{id}` | 批次详情：落库行、旗号详情、隔离队列、未接纳 |
| GET | `/api/flag-policy` | 当日策略、可选出路、锁定原因 |
| PUT | `/api/flag-policy` | 写入当日出路 |
| GET | `/api/quarantine` | 隔离队列，可按 `status` 过滤 |
| POST | `/api/quarantine/{id}/review` | 复核一行，腾出队列 |
